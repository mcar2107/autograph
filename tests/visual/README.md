# Эталонные скриншоты

`__screenshots__/<Компонент>/<Story>_chromium-linux.png` — эталоны для `npm run test:visual`. Снимаются и сверяются
только в docker-образе Playwright: рукописные шрифты растрируются в macOS и Linux по-разному, и локальный снимок с
прогоном в образе не сойдётся. Платформа зашита в имя файла, поэтому прогон вне linux не сверится с чужими эталонами
молча — он просто не найдёт эталона.

Снимаются не все stories: пробы на настоящем измерителе и в настоящем воркере — переносы и пагинация
(`RealLayout.stories.tsx`), попадание базовых линий на разлиновку (`BaselineFit.stories.tsx`,
`RasterRuling.stories.tsx`, `MarkupOverlayFit.stories.tsx`, `LinesTool.stories.tsx`), разбор снимка в воркере
(`MeasureSheetWorker.stories.tsx`) — проверяют расчёт, а не внешний вид; список исключений в
`.storybook/visual-setup.ts`.

Редактор разметки снимается на фиксированных листах пресет-пака с фиксированным seed:
`SheetMarkupEditor.stories.tsx` — третий лист клетки по инструменту и зеркальная страница,
`MarkupPrecision.stories.tsx` и `BendTool.stories.tsx` — первый лист линейки в состоянии после их проверок.

Обновить эталоны после осознанной правки вёрстки — `npm run test:visual:update`: он прогоняет те же тесты с `--update`
и перезаписывает эталоны текущим рендером. Диф после этого смотреть в `git diff`, а не в отчёте прогона.

Обе команды идут только через docker-образ (`npm run visual:docker` под капотом): запустить скриншотный прогон в
хостовом окружении нечем — и специально, иначе в репозиторий попали бы эталоны, снятые не в linux.

`.attachments/` — снимки упавших тестов (`actual` и `diff`), которые кладёт vitest. Каталог в `.gitignore` и
пересоздаётся прогоном.
