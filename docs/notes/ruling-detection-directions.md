# Распознавание разлиновки: куда дальше

Записано 2026-09-23, при постановке #19 (редактор разметки). Контекст: к этому моменту `lib/paper` — около 11 тыс.
строк и больше сотни порогов, подобранных на одних и тех же 26 живых снимках; четыре задачи подряд (#8–#11) закрывали
по снимку и находили следующий кейс. #19 меняет роль автомата — он предлагает, пользователь правит поверх фото; #10 добавляет
вето линии поля по цвету и отказ вместо фантома. Ниже — направления, которые сознательно отложены.

## Почему каскад порогов упирается

Разбор идёт каскадом: профиль → шаг по полосам → угол → перспектива → второй проход → изгиб → поля → линия поля. Каждая
ступень принимает своё решение по своему порогу и отдаёт результат следующей:

- ошибка ранней ступени протекает во все поздние;
- каждая ступень видит только свой кусок улик, поэтому новый кейс лечится новым вето или порогом;
- пороги подобраны на тех же снимках, на которых проверяются, — удержанной выборки не было до #19.

## Направление 1: одна модель, робастная подгонка по отрезкам

Два слоя вместо каскада.

1. **Собрать улики, ничего не решая.** Детектор отрезков (LSD — Line Segment Detector; близкий по смыслу — Hough)
   выдаёт все короткие прямые отрезки кадра: концы, направление, контраст. Туда попадёт всё — клетка, край стола,
   буквы, тени; отсеивать на этом шаге не нужно.
2. **Подогнать одну модель всего листа.** Идеальная сетка на плоском листе проецируется в кадр гомографией (8 чисел:
   поворот, наклон, перспектива, масштаб разом) плюс шаг и фаза. Подгонка — RANSAC: взять случайные 3–4 отрезка,
   вычислить модель, посчитать согласных (отрезки на её линиях в пределах пары пикселей), повторить сотни раз, взять
   модель с наибольшим согласием, уточнить наименьшими квадратами по согласным.

```
фото → [отрезки: тысячи, мусор тоже] → RANSAC → гомография + шаг + фаза
                                                 └→ доля согласных = уверенность
```

Что даёт:

- одно решение вместо десяти; угол, перспектива и шаг — параметры одной модели, а не ступени;
- одна мера качества — доля согласных и их невязка — вместо сотни констант;
- изгиб — остаток после модели; линия поля — вертикаль в координатах листа, проверяется после подгонки (и цветом);
- у клетки две семьи линий → две точки схода → гомография почти напрямую.

Оговорки:

- пороги у RANSAC тоже есть (допуск в пикселях, число итераций), но их мало и они физические;
- у линейки без вертикалей одна семья линий гомографию не задаёт — нужны края листа;
- это переписывание ядра `lib/paper`, цена не оценена; на наших снимках подход не проверен;
- LSD на 12 Мп в браузере — только на уменьшенной копии.

Когда браться: если после #19 правка в редакторе остаётся частой — то есть автомат ошибается на заметной доле
снимков удержанной выборки.

## Направление 2: ML-сегментация

Сеть раскрашивает пиксели: «линия», «линия поля», «фон». Геометрия поверх остаётся своей.

### Открытых датасетов под задачу нет (поиск 2026-09-23, не исчерпывающий)

| Датасет | Что там | Почему не подходит |
|---|---|---|
| [DocDewarpHV](https://github.com/xiaomore/DocDewarpHV) ([D2Dewarp](https://arxiv.org/abs/2507.08492)) | Разметка горизонтальных и вертикальных линий на искажённых документах | Синтетика (рендер), линии — структура печатного документа, не разлиновка; CC BY-NC-ND, только некоммерческие исследования |
| DocUNet (130 фото), DIR300 (300), WarpDoc (1020) — [обзор](https://arxiv.org/html/2507.19804v1) | Настоящие фото документов с перспективой, изгибом, заломами | Эталон — плоский скан, линии не размечены; печатные документы, не тетради |
| DIVA-HisDB, Horae, READ-BAD — [обзор](https://arxiv.org/pdf/2012.14163) | Размеченные строки текста | Старинные рукописи, размечен текст, а не разлиновка |
| [Ink and Identity](https://data.mendeley.com/datasets/2nm9cp89df/4) | 450 фото рукописи с iPhone | Бумага без разлиновки |

Приём, который стоит взять у D2Dewarp: **автоматическая разметка синтетикой** — реальные фото чистых листов искажаются
известной гомографией и изгибом, и разметка получается точной и бесплатной. Продолжение `tests/helpers/synthetic-sheet.ts`.
Минус — разрыв с реальностью: тени, пружина, стол.

### Сколько нужно данных (ориентиры, не замер)

- **Удержанная выборка для проверки**: при нуле ошибок на *n* снимках доля ошибок с уверенностью 95 % не выше ≈ 3/*n*
  («правило трёх»): 30 → ~10 %, 50 → ~6 %, 100 → ~3 %. Разнообразие важнее числа: сто снимков одной тетради — один пример.
- **Обучение**: с нуля — тысячи, нереально. Реалистично — предобученная сеть, основной объём из синтетики (у Doc3D ~100 тыс.
  синтетических изображений), живые фото — донастройка: грубо 200–500 на обучение + 50–100 на тест. Точно — только
  кривая обучения (50 → 100 → 200 и смотреть, где качество перестаёт расти). Задача пиксельная: на каждом фото тысячи
  размеченных пикселей линий, поэтому снимков нужно меньше, чем в классификации.
- **Цена разметки**: с редактором #19 (правка предложения автомата) — около минуты на фото, 300 фото ≈ 5 часов.

**Источник данных — сам редактор #19**: каждая правка пользователя поверх снимка — размеченный пример. Если когда-то
понадобится ML, выгрузка «фото + сохранённая разметка» из редактора даст датасет без отдельной разметки.

### Запуск в браузере

Технически реально:

- **ONNX Runtime Web** (обучение в PyTorch → `.onnx`, WebGPU с фолбэком на WASM) или **TensorFlow.js**; работа в Web
  Worker, как отрисовка.
- Лёгкий сегментатор (U-Net на MobileNet-энкодере) — порядка 2–10 МБ, после int8-квантования в разы меньше; вход —
  уменьшенная копия 512–1024 px, точная подгонка — геометрией на полном кадре.
- Время — от десятков миллисекунд (WebGPU) до порядка секунды (WASM) на фото; импорт разовый, это приемлемо.
- WebGPU на момент записи не входит в `baseline widely available` (порог `.browserslistrc`) — WASM-фолбэк обязателен.

Что заденет в проекте:

- **Офлайн**: `maximumFileSizeToCacheInBytes` в `vite.config.ts` — 2 МиБ; WASM-рантайм ONNX и модель, вероятно, больше.
  Либо поднять порог, либо грузить модель лениво при первом импорте листа со своим кэшем; расширения `.onnx`/`.wasm` —
  в `globPatterns`, иначе упадёт `npm run test:pwa`.
- **Детерминизм**: WebGPU и WASM могут расходиться в последних знаках — сторож «`profiles.json` бит-в-бит» станет
  сверкой с допуском.
- `npm run build:paper` уже идёт через Chromium — тот же рантайм заработает и там.

### Как встраивать, если дойдёт

Гибрид: модель заменяет только нижний, самый хрупкий слой — вместо профиля яркости отдаёт карты «вероятность линии» и
«вероятность линии поля». Подгонка шага, перспективы, изгиба (или RANSAC из направления 1) остаётся своей. Модель
снимает главный источник кейсов — тени, текст, стол, пружину, — а результат остаётся объяснимым числами, и
`measure:sheet` по-прежнему печатает, почему принято решение.

Когда браться: когда накоплено 300+ размеченных живых фото (реалистично — из правок в редакторе) и направление 1 не
закрыло частоту правок.

## Открытые наблюдения

- **Нецветная линия поля** (синяя, фиолетовая, выцветшая до серого) после вето по цвету из #10 не находится — это безопасная ошибка,
  пользователь добавит линию в редакторе. Если такие тетради встречаются часто — собрать снимки сюда и решать отдельно.
